Notes

Decisions made

  • What is a link: only done cards (green core). Their Sidekick changed a record, so there is a place to show. Repair and grow cards stay as they are today, not links (founder, 2026-10-31: "stays as is"). Not Done (red, Try Again), working and Waiting for Connection cards changed nothing and are not links.
  • Look of a link: none. No chevron, no underline, no colour (DESIGN 1a). A done card darkens a step under the finger and opens; other cards don't react.
  • Big and slim cards both open. Tucked cards (edges only) don't.
  • Open = a normal push from the right (iOS, 350 ms), on top of jess (founder, 2026-10-31). Back = the left edge: Sidekick → jess → Midas home. No back chip, no words. jess's stack keeps its place while you are away.
  • The page opens already at the record, centred on screen. If the record is in another list, month or day, the page opens that one. No scroll animation.
  • The mark: Volt wash behind the record's row with a 3 pt ink edge on its left (founder, 2026-10-31). Volt fades in in 180 ms as the push lands, holds 1.2 s, fades out over 1.2 s. One look in every Sidekick, drawn by the shell's SDK, not by each page.
  • New: the row, marked. Nothing else.
  • Edited: the row, marked; the field that changed shows the old value struck through before the new one ("Thu, Nov 5, 10:00 AM 3:00 PM", under Fri, Nov 6). The old value stays until you leave the page; the Volt fades.
  • Deleted: a ghost row in its old place: struck through, dashed check, with Undo (ink pill). It stays until you leave the page. Undo puts the record back as it was and marks it again (WRITING 8: undo over a confirmation).
  • No longer there (deleted by hand later): the Sidekick opens at its top with "Already Deleted" as an ink toast for 2.5 s. Changed by hand later: it opens at the record as it is now, marked; no old value.
  • jess becomes a screen in Midas's own navigation, so the edge swipe from jess goes to Midas home. Today jess is a full-screen cover.
  • Shell light mode only, like the Workdesk and Photo mockups.

Open questions (my default in grey)

  • Volt mark: fade or stay until you leave? Default: fades (1.2 s hold, 1.2 s fade). "Stays" is in the controls to compare.
  • A task that changed several records (a list with its reminders, a receipt and later an edit): which one does it open at? Default: all of them are marked; the page opens at the first.
  • After Undo, what does the Workdesk card do? Default: stays as it was; a tap then shows the record back in place, marked as new.
  • Money: open at the expense's row in the month (as shown), or at its detail screen (jess-photo note said "opens Money at that expense")? Default: the row in the month, so every Sidekick behaves the same; one more tap for the detail.
  • A completed reminder: open in Completed, or count it as no longer there? Default: open the list with Completed shown, the reminder marked.
  • Home result cards (top of Midas): links too? Default: yes, same behaviour; back goes to Midas home (one level).
  • A Sidekick removed since: Default: the card stops being a link; no toast.

Build notes (for later, no code now)

  • Card keeps the link. JessResultCard gets link: { sidekickId, changes: [{ key, op, before }] }, filled in JessRouter.run right where the ops are applied: .set on a key that wasn't there = new, .set on an existing key = edit (keeps the old value as before), .delete = delete (keeps the old value for Undo). Only done cards get one. Kept with the 200-task log; before values drop after 7 days to keep the file small.
  • Navigation. jess moves from fullScreenCover into the home NavigationStack (path [jess], then [jess, sidekick]). SidekickRouter.open(sidekickId:focus:) appends instead of replacing the path. SwipeBackEnabler already gives the edge swipe.
  • Passing the focus. The shell adds a WKUserScript at document start: window.__midasFocus = { key, op, before }. Not in the URL, so a page's own routing and a reload don't see it again.
  • SDK hook, in the store snippet every page already pastes: store.focus() returns the focus or null; the page shows the list, month or day holding that key, then calls store.markChange(element). The SDK does the rest the same everywhere: centre the element, Volt wash, struck old value for edit, ghost row and Undo for delete. Undo is store.set(key, before), a normal write that syncs.
  • What each page needs: data-key="<record key>" on every record's element; open the container that holds a key (Reminders: its list, and Completed when done; Money: the expense's month; Water: that day's log; Care Reminders: its list); for a deleted key, render a ghost row from before. If no element has the key, the page calls store.markChange(null) and the shell shows "Already Deleted".
  • Per Sidekick, today: Reminders: rows for reminder: and list: keys, list switch. Water: rows for water: entries, day switch; goal and unit changes (settings:) mark the goal number. Care Reminders: like Reminders, plus list: alerts. Money (not built yet): rows for expenses, month switch.
  • Generator and repair agents: the Sidekick template carries data-key and the store.focus() call; the repair agent's rules keep both. No new tool in tools.js: Undo is the shell's own write, not a jess action.
  • Tests: shell unit tests for the link captured from new, edit and delete ops and for the push path; a guard test per Sidekick that, given a focus key, the page renders exactly one element with that data-key.

Known limits: HTML doesn't show iOS springs, haptics, the real edge-swipe feel or exact text wrapping. A Midas Test build checks the feel.
