The shield: what no repair may break

  1. Core checks owned by Midas, not by the copynew Kept outside the person's tests/. No repair and no guardian can change them.
  2. The page opensnew Load it in a real WebKit with the person's own records: every view draws, no errors.
  3. Every jess tool still worksnew Run every tool on a copy of the person's records before and after. Same answers, unless the request names that tool. Each tool's page control still exists.
  4. Settings staynew The settings engine and set_setting are core. The panel can be hidden; the engine can't be removed.
  5. Records and widget Every stored record still fits (already built). The widget record is still written.
  6. Primitive blocks keep their behaviournew The TD-* / block tests run on every copy, read-only.
  7. New features go in their own blocknew Edits to core blocks are listed and need the guardian. A built feature is saved; the next same request starts from it.
  8. "Remove" means hidenew A setting turns it off; its tool stays and answers "turned off". Turning it back on is a setting too.
  9. Preferences never become tests Colour, wording, position, show/hide live in settings. Tests check what works, not how it looks (founder, 2026-10-30).
