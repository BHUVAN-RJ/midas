## 2. Decided

**Records** (`manifest.json` `types`):
- `sound:<id>`, `$type` `soundboard.sound`: `name` (string), `tags` (array of strings, optional),
  `audio` (`"file:<id>"`), `image` (`"file:<id>"`, optional; a GIF or any image), `order` (number),
  `starter` (string, optional: the starter key it came from), `createdAt` (ISO string).
- `settings:self`: `seeded` (array of starter keys already copied in, so a deleted starter stays
  deleted), `overlap` (boolean, default true: tapping another tile plays over the current one).

**Starter sounds.** Files in `sidekicks/soundboard/starter/` (already there, compressed: GIFs 128 px,
mp3 64 kbps mono). They go into the page as one data block at the very end of `<body>`:
`<script type="application/json" id="starter-sounds">` with `[{key, name, tags, audioType,
audioBase64, imageType, imageBase64}]`, one asset per line, generated by a small script
(`backend/scripts/soundboard-starter.mjs` or similar) that rewrites only that block, so it can be
re-run when a sound is added. On open, for every starter whose key is not in `settings:self.seeded`:
`store.putFile` the audio and the GIF, `store.set` the `sound:` record, add the key to `seeded`.
Starters, in order:

| key | name | tags | audio | GIF |
|---|---|---|---|---|
| fahh | Fahh | fah, fail | fahh.mp3 | fahh.gif |
| bruh | Bruh | bruh | bruh.mp3 | bruh.gif |
| boom | Vine Boom | boom, rock | boom.mp3 | boom.gif (the Rock eyebrow) |

(A fifth, the old man "what the fuck is going on here", waits for the founder to name the clip.)
Check the data block is a non-executable script type, so the deploy's script hashes and the CSP
are unaffected; confirm how `deploy-sidekick.mjs` / bundle tools hash scripts and that the gate passes.

**Playback.** The CSP has no `media-src` (falls back to `default-src 'none'`), so `<audio>` and
`new Audio()` are blocked. Play through Web Audio: fetch the bytes from the page's own origin
(`location.origin + '/_midas/files/<id>'`, which `connect-src` allows; a `blob:` URL may not be),
`decodeAudioData`, cache the decoded buffer per sound, `AudioBufferSourceNode` per tap. Create or
`resume()` the AudioContext inside the tap. Overlap by default; Stop stops all. Normal volume; the
silent switch muting it is fine (founder, 2026-11-07: "dont really need" playing through silent).
Images: `<img src>` from `store.fileUrl` (blob: is allowed by `img-src`), animated GIFs play.

**Adding.** "+" → Add Sound sheet: Choose Sound (`<input type=file accept="audio/*">`), Choose GIF
(`accept="image/*"`, optional), Name (filled from the file name), Tags, Save. Edit = same sheet
filled. Delete = long-press menu, undo toast preferred over a confirm (WRITING.md rule 8).
Reminders already uses a file input (`sidekicks/reminders/index.html:411`).

**Search.** Filters name + tags as you type, case-insensitive. No results: "No Sounds".

**Agent tools** (`manifest.json` `agent` block + `tools.js`, reusing page code): at least
`soundboard.list`, `soundboard.search` (query), `soundboard.rename`, `soundboard.delete`,
`soundboard.tag`. Playing from jess (outside the page) is not possible without a shell change:
leave it out and list it as later. Follow hydration's pattern exactly, including the
"copied from index.html" block the deploy gate checks.

**Widget:** small size at least, light and dark, per `docs/WIDGETS.md` (what fits: the sound count
and the first few names, or whatever the template allows without a shell change). Add Widget in the
"?" menu.

**Repair agent:** `runner/agents/soundboard.md` (model: `runner/agents/hydration.md`) and the
`TEMPLATE_BY_SIDEKICK` entry. The agent file tells the repair agent that the `starter-sounds` data
block is generated: never edit it by hand, never read it whole.

## As built (2026-11-07)

- The starter block is a `<template id="starter-sounds">`, not a `<script type="application/json">`:
  the deploy gate refuses any script tag with attributes (`bundle-tools.mjs`, "script tag with
  attributes"). A template's text never runs and is not hashed. Generator:
  `backend/scripts/soundboard-starter.mjs` (list in `sidekicks/soundboard/starter/starters.json`;
  `--check` exits 1 when the block is out of date). A fifth starter = its files + one line in
  `starters.json` + run the script.
- Starter record keys are fixed (`sound:fahh`), so two phones that copy a starter in before they
  sync write the same record instead of two.
- "One at a Time" in the "?" menu sets `settings:self.overlap`; it has its tool,
  `soundboard.set_overlap`.
- Tools: `soundboard.list`, `.search`, `.rename`, `.tag` (add / remove), `.delete`,
  `.set_overlap`. Deleting a starter by voice also adds its key to `seeded` when missing.
- Tile light and dark (`docs/ICONS.md`): `icon.background` `#FFE600`, `icon.backgroundDark`
  `#B3A100` (same hue, 70% brightness, as Reminders' `#FF9500` / `#B36800`). The repair agent
  carries the icon rule and `{{ICONS}}`.
- jess work log links: the page pastes the store helper with `store.focus()` / `markChange`, and
  every tile carries `data-key="sound:<key>"`, so a work log card opens Sounds with the changed
  sound marked (check: `backend/test/soundboard-worklog.test.ts`). A deleted sound has no tile;
  nothing is marked for it.
